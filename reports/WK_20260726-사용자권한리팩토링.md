# 개요

사용자 및 권한 워크스트림 리팩토링을 진행했다.
컨트롤러마다 흩어져 있던 `Jwt subject -> userId` 변환을 공통 표현으로 통일하고, 매장 멤버 권한 체크가 `requireRole` 하나에만 의존하던 구조를 역할 의도가 드러나는 메서드 집합으로 정리했다.

# 이슈

- 작업 시점에 `jariyo-docs` 디렉터리에 기존 변경사항이 있어 해당 변경은 건드리지 않았다.
- 이번 작업은 외부 API 응답 구조를 바꾸지 않고 사용자 식별 방식과 권한 체크 표현을 정리하는 범위로 제한했다.

# 후속 작업

- `AuthenticatedUser`를 Spring MVC argument resolver 또는 annotation 기반으로 확장할지 검토
- 운영자 API가 늘어날 것을 대비해 `StoreAuthorizationService`에 매장별 세부 권한 정책을 추가할지 검토
- 예약, 대기, 현장 운영 서비스에 공통 사용자 컨텍스트를 더 깊게 전파할 구조를 설계

# 셀프리뷰

- `06-backend-implementation-guide.md`, `04-api-spec.md`의 사용자/권한 관련 범위를 다시 확인하고 작업했다.
- `GET /api/v1/me` 문서 구조와 현재 구현이 어긋나지 않도록 외부 계약은 유지했다.
- `./gradlew test`로 전체 회귀를 확인했다.
- `reports`에 작업 보고서를 추가했다.
