# 매장 운영 설정 관리

## 개요

이슈 #37의 매장 정보·정책, 서비스, 직원, 영업시간과 일정 예외 쓰기 API를 구현했다. 기존 조회 API와 예약 가능 시간 규칙을 재사용하고, 미래 활성 예약과 충돌하는 설정은 저장하지 않고 충돌 예약을 반환하도록 했다.

## 변경 파일

* 매장 설정 컨트롤러와 `StoreSettingsService`
* 매장·직원·서비스 엔티티 및 저장소
* 예약 저장소와 예약 생성 잠금 순서
* `ScheduleRangeResolver`와 관련 단위·통합 테스트
* `jariyo-docs` 계획, 데이터 모델, API, 프론트엔드, 백엔드 가이드

## 실행 명령

```powershell
.\gradlew.bat compileJava
.\gradlew.bat test
.\gradlew.bat integrationTest
.\gradlew.bat build
git diff --check
git status --short
git diff --stat
git diff
```

## 이슈

* sandbox 실행에서는 Gradle 배포본 다운로드 권한 오류가 발생해 승인된 외부 실행으로 통합 테스트를 완료했다. 중첩 실행으로 손상된 테스트 결과 캐시는 `clean` 후 단일 실행으로 재검증했다.
* 설정 API는 공통 명세의 멱등성 적용 대상이 아니므로 `Idempotency-Key`를 요구하지 않는다.

## 후속 작업

* Ponytail 재검토에서 확인된 미사용 코드와 불필요한 옵션을 제거했다.
* 충돌 예약 강제 취소·강제 설정 적용은 MVP 이후로 유지한다.

## 셀프리뷰

* 기존 조회 API, 권한 서비스, 감사 로그와 예약 잠금을 재사용했다.
* 별도 관리자 조회 API, 신규 의존성, DB 마이그레이션을 추가하지 않았다.
* 다른 OWNER 변경과 마지막 활성 OWNER 제거를 차단했다.
* 충돌 시 설정과 감사 로그가 남지 않는 원자성을 단위·통합 테스트로 확인했다.
* 관련 문서 5종을 구현 계약과 일치하도록 갱신했다.
* 전체 검증 후 사용자 지시에 따라 문서와 백엔드 변경을 Ready for review PR로 게시한다.
