## 개요

이슈 `#54 예약 가능 시간 조회 부하 테스트`를 재현 가능한 저장소 자산으로 정리했다.
로컬 부하 환경에서 바로 실행할 수 있도록 `k6` 시나리오, 시드 SQL, 실행 문서를 추가했다.

## 변경 파일

- `load-tests/k6/availability-load.js`
- `docker/local-load/sql/seed-availability-load-test.sql`
- `jariyo-docs/docs/14-local-load-test-environment.md`
- `reports/WK_20260827-예약가능시간조회부하테스트.md`

## 실행 명령

- `./gradlew test`
- `k6 version`
- `docker compose -f docker-compose.local-load.yml up --build -d`
- `docker exec -i jariyo-local-postgres psql -U jariyo -d jariyo < docker/local-load/sql/seed-availability-load-test.sql`
- `curl -X POST http://127.0.0.1:8080/api/v1/auth/sign-up`
- `curl -X POST http://127.0.0.1:8080/api/v1/auth/sign-in`
- `docker run --rm --network host -v /home/noobth/github/jariyo-backend:/work -w /work -e K6_PROFILE=base -e K6_BASE_URL=http://127.0.0.1:8080 -e K6_AUTH_TOKEN={token} grafana/k6 run /work/load-tests/k6/availability-load.js`
- `docker run --rm --network host -v /home/noobth/github/jariyo-backend:/work -w /work -e K6_PROFILE=stressed -e K6_BASE_URL=http://127.0.0.1:8080 -e K6_AUTH_TOKEN={token} grafana/k6 run /work/load-tests/k6/availability-load.js`

## 이슈

- 현재 작업 환경에는 `k6` 바이너리가 설치되어 있지 않아 Docker 기반 `grafana/k6`로 실행했다.
- 초기 시드 SQL에서 `reservation.customer_id` 참조 대상을 잘못 넣어 1회 적재가 실패했고, `customer_profile.id` 기준으로 수정했다.
- 초기 `k6` 스크립트가 `URLSearchParams`를 사용해 런타임 예외가 발생했고, `k6` 호환 문자열 빌더로 수정 후 재실행했다.
- `base`, `stressed` 모두 오류율은 0%였지만 응답 시간 기준을 크게 초과했다.
