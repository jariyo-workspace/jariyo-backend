# 개요

예약 계산 워크스트림 리팩토링을 진행했다.
`AvailabilityService`에 섞여 있던 입력 검증, 계산용 조회 그래프 로딩, 날짜별 슬롯 계산 책임을 분리해 계산 컨텍스트 중심 구조로 정리했다.

# 변경 파일

- `src/main/java/com/example/jariyo_backend/domain/availability/service/AvailabilityService.java`
- `src/test/java/com/example/jariyo_backend/domain/availability/service/AvailabilityServiceTests.java`

# 실행 명령

- `./gradlew test`

# 테스트 결과

- `./gradlew test` 통과

# 이슈

- 작업 시점에 `jariyo-docs` 디렉터리에 기존 변경사항이 있어 해당 변경은 건드리지 않았다.
- 이번 작업은 예약 가능 시간 API의 외부 응답 구조를 바꾸지 않고 계산 내부 구조와 경계 검증을 정리하는 범위로 제한했다.

# 후속 작업

- 예약 생성 시 슬롯 재검증 로직이 `AvailabilityService` 계산 규칙을 직접 재사용할지 별도 검증 컴포넌트로 분리할지 결정
- `UNAVAILABLE`, `WAITLIST_AVAILABLE` 상태까지 응답에 포함할지 문서와 구현 차이를 검토
- 계산용 `AvailabilityContext`를 별도 클래스로 승격해 예약 도메인과 공유할지 검토

# 셀프리뷰

- `04-api-spec.md`, `05-frontend-api-guide.md`, `06-backend-implementation-guide.md`를 다시 확인하고 예약 계산 범위에 맞춰 작업했다.
- `bookingOpenDays`, `minimumBookingNoticeMinutes`, `partySize` 같은 입력 경계가 계산 서비스 내부에서도 검증되도록 보강했다.
- `./gradlew test`로 전체 회귀를 확인했다.
- `reports`에 작업 보고서를 추가했다.
- 현재는 계산 컨텍스트를 `AvailabilityService` 내부 record로 유지하고 있어 재사용 범위가 더 커지면 별도 타입 분리가 필요하다.
