## 개요

이슈 `#29` 범위로 관리자 운영 상세 통계 3종을 추가했다. 일별 예약 상태 집계, 직원별 예약 처리 현황, 서비스별 실제 평균 소요 시간을 기존 운영 통계 API 축에 맞춰 확장했다.

## 변경 파일

* `src/main/java/com/example/jariyo_backend/domain/admin/controller/AdminOperationsController.java`
* `src/main/java/com/example/jariyo_backend/domain/admin/service/AdminAnalyticsService.java`
* `src/main/java/com/example/jariyo_backend/domain/walkin/entity/ServiceSession.java`
* `src/main/java/com/example/jariyo_backend/domain/walkin/repository/ServiceSessionRepository.java`
* `src/test/java/com/example/jariyo_backend/domain/admin/controller/AdminOperationsControllerTests.java`
* `src/test/java/com/example/jariyo_backend/domain/admin/service/AdminAnalyticsServiceTests.java`
* `jariyo-docs/docs/04-api-spec.md`

* `./gradlew test --tests "com.example.jariyo_backend.domain.admin.controller.AdminOperationsControllerTests"`

## 이슈

* 직원별 통계의 실제 처리 시간은 현재 `service_session`이 존재하는 현장 서비스 완료 데이터 기준으로만 계산한다.
* 예약 완료 건에는 실제 시작·종료 시간이 아직 없어서 직원별 평균 처리 시간과 서비스별 실제 소요 시간 집계에 포함하지 않았다.

## 후속 작업

* 예약 서비스 완료에도 실제 시작·종료 시각을 남길지 도메인 기준을 확정한다.
* 운영 화면 요구사항에 맞춰 직원별 가동률, 예약 지연 시간 같은 파생 지표를 추가 검토한다.
* 상세 통계 응답에 인사이트 문구나 비교 기간 메타데이터가 필요하면 별도 계약으로 확장한다.

## 셀프리뷰

* 관련 문서 `04-api-spec.md`를 현재 구현 필드 기준으로 갱신했다.
* 브랜치는 `feature/admin-analytics-detail`에서 작업 중이며 `master` 직접 수정 규칙을 지켰다.
* 관리자 권한 검증은 기존 요약 통계와 같은 `requireManager` 경계를 유지했다.
* 전체 테스트 `./gradlew test`까지 확인해 회귀 범위를 점검했다.
