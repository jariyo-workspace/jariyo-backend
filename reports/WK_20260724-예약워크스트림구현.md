# 예약 워크스트림 구현

## 개요

- 이슈 #9 범위의 일반 예약 생성, 내 예약 목록·상세·상태 이력 조회, 고객 취소 API를 구현했다.
- 일반 예약은 홀드 없이 즉시 `CONFIRMED`로 저장하고 `CREATED` 상태 이력을 함께 기록한다.
- 직접 예약과 빈자리 제안 수락이 동일한 PostgreSQL advisory lock, 중복 검사, 예약·이력 저장 경로를 사용하도록 통합했다.
- 구현 계약에 맞춰 데이터 모델, API 명세, 프론트엔드 가이드, 백엔드 구현·MVP 가이드를 수정했다.
- Git stage, commit, push, PR 생성 및 GitHub 이슈 변경은 수행하지 않았다.

## 이슈

- 격리 환경에서 통합 테스트 최초 실행 시 Gradle 배포 파일 다운로드가 네트워크 권한으로 차단됐다. 기존 Gradle 캐시와 Docker를 사용할 수 있는 승인된 실행으로 재시도해 전체 테스트를 통과했다.
- 멱등성 응답 역직렬화 시 `OffsetDateTime`이 UTC로 보정되던 공통 동작을 발견해, 저장 당시 offset을 유지하도록 수정하고 통합 테스트로 확인했다.
- 기존 스키마는 `assigned_staff_id`를 nullable로 허용하므로, 과거 또는 수동 예약 조회에서 담당 직원이 없어도 목록·상세 API가 실패하지 않도록 처리했다.
- Ponytail 셀프리뷰 후 사용되지 않는 대기 예약 팩토리와 예약 생성 내부의 미래 확장용 actor 필드를 제거하고, 예약 시간 검증에서 `Clock`을 한 번만 읽도록 단순화했다.

### 후속 이슈 초안 2: 내 예약 목록 cursor 페이지네이션

- `startAt DESC, id DESC` 정렬에 맞는 opaque cursor 정의
- `cursor`, `limit`, `nextCursor` 요청·응답 계약 추가
- 상태·날짜 필터와 cursor 조합 및 경계값 테스트

GitHub에는 위 후속 이슈를 등록하지 않았다. 구현 순서는 예약 홀드, cursor 페이지네이션 순으로 권장한다.

- 취소 마감 시각과 같은 시각은 `now.isAfter(deadline)`이 아니므로 취소 가능하다.
