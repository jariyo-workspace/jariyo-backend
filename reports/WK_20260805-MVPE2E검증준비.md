## 개요

MVP 대상 E2E 검증을 시작하기 위해 이슈 #49를 기준으로 작업 브랜치 `chore/mvp-e2e-validation`을 생성하고, 자동 검증 범위와 수동 E2E 절차를 합친 실행 프로세스를 정리했다.

## 변경 파일

- `reports/WK_20260805-MVPE2E검증준비.md`
- `reports/WK_20260805-MVPE2E검증프로세스.md`
- `src/integrationTest/java/com/example/jariyo_backend/admin/AdminReservationWorkflowIntegrationTests.java`

## 실행 명령

- `git branch --show-current`
- `git status --short`
- `git checkout -b chore/mvp-e2e-validation`
- `GRADLE_USER_HOME=/tmp/gradle-home GRADLE_DAEMON_BIND_ADDRESS=127.0.0.1 ./gradlew --no-daemon test`
- `GRADLE_USER_HOME=/tmp/gradle-home GRADLE_DAEMON_BIND_ADDRESS=127.0.0.1 ./gradlew --no-daemon integrationTest --tests com.example.jariyo_backend.admin.AdminReservationWorkflowIntegrationTests`
- `GRADLE_USER_HOME=/tmp/gradle-home GRADLE_DAEMON_BIND_ADDRESS=127.0.0.1 ./gradlew --no-daemon integrationTest`

## 테스트 결과

- `test`: 성공
- `integrationTest`: 성공
- `integrationTest --tests com.example.jariyo_backend.admin.AdminReservationWorkflowIntegrationTests`: 성공
- 기본 `./gradlew` 실행은 샌드박스의 Gradle 홈 및 소켓 제약으로 실패했고, `GRADLE_USER_HOME=/tmp/gradle-home GRADLE_DAEMON_BIND_ADDRESS=127.0.0.1 ./gradlew --no-daemon ...` 조합으로 재실행해 통과했다.
- 2026년 8월 5일 기준으로 다음 MVP 핵심 시나리오를 통합 테스트로 확인했다.
- 인증: 회원가입, 로그인, refresh token 재발급, 재사용 감지, 로그아웃, 내 정보 조회
- 예약: 생성, 목록/상세/이력 조회, 취소, 멱등성, 겹침 방지, 페이지네이션, 취소 마감
- 예약 대기: 신청, 빈자리 제안 생성, 수락, 만료, 직접 예약과의 경합
- 현장 대기: 등록, 호출, 호출 응답, 체크인, 서비스 시작/완료, 대기열 재계산, 호출 만료
- 운영자 예약 처리: 당일 운영 조회, 예약 체크인, 서비스 시작, 서비스 완료, 최종 상태 조회

## 이슈

- 워크트리에 기존 `jariyo-docs` 변경사항과 미추적 report 파일이 있어, 해당 상태를 유지한 채 브랜치만 분기했다.

## 후속 작업

- 이슈 #49 기준으로 수동 API 호출 순서의 E2E 시나리오를 API 컬렉션 또는 스크립트로 구체화한다.
- 검증용 계정, 매장, 예약/대기/현장 데이터 시드를 준비한다.
- 브라우저 또는 API 클라이언트 기준의 실제 요청/응답 로그를 남기는 수동 E2E를 추가로 수행한다.

## 셀프리뷰

- 브랜치/이슈 규칙은 준수했다.
- 문서 변경이 필요한 작업은 아니어서 `jariyo-docs/docs`는 수정하지 않았다.
- 자동 검증과 수동 E2E를 분리해 기록하도록 프로세스를 정리했다.
- `test`, `integrationTest`를 실제로 실행해 현재 코드 기준의 출발점을 확인했다.
- 운영자 예약 처리 흐름이 기존 통합 테스트에서 비어 있어 시나리오 테스트를 추가해 공백을 메웠다.
