# 개요

이슈 `#11` 범위로 예약 대기 신청/조회/취소, 빈자리 제안 조회/수락, 예약 취소 시 자동 제안 생성, 제안 만료 복귀 흐름을 구현했다.

관련 문서는 `jariyo-docs/docs/04-api-spec.md`, `02-data-model.md`, `06-backend-implementation-guide.md`, `07-backend-mvp-guide.md`를 확인했고, 이번 구현은 기존 문서 범위에 맞춰 진행해 별도 문서 수정은 하지 않았다.

# 이슈

- 샌드박스 기본 Gradle 캐시 경로가 읽기 전용이라 `integrationTest`는 `GRADLE_USER_HOME=/tmp/gradle-home`으로 우회 실행했다.
- 통합 테스트 실행에는 Gradle 배포본 다운로드와 Testcontainers 접근이 필요해 권한 상승이 필요했다.
- 현재 워크트리에는 이번 작업과 별개로 `jariyo-docs` 변경이 이미 존재한다.

# 후속 작업

- 예약 생성/조회 본편이 들어오면 `ReservationController`를 대기/제안 흐름과 같은 수준으로 확장해야 한다.
- 운영자용 예약 대기 목록, 수동 제안 생성/취소, 제안 거절 API는 아직 구현하지 않았다.
- 예약 상태 이력과 빈자리 제안 상태 이력을 외부 조회 API로 노출하는 작업이 남아 있다.

# 셀프리뷰

- 관련 문서를 먼저 확인했고, 이번 구현은 문서에 이미 정의된 계약을 따르도록 맞췄다.
- 예약과 대기 사이 고객 식별자 경계가 `users.id`와 `customer_profile.id`로 나뉘어 있어 수락/취소 경로에서 변환을 명시적으로 처리했다.
- 만료 처리를 스케줄러와 조회 시 정리 로직으로 둘 다 걸어 두었지만, 대량 데이터 환경에서는 배치 크기나 인덱스 전략을 추가 검토할 필요가 있다.
- 브랜치는 `feature/reservation-waitlist-offers`에서 작업했고, 커밋과 푸시는 아직 하지 않았다.
