# 개요

`AuditLog` 엔티티는 존재하지만 `audit_log` 테이블 생성 migration이 없어 새 PostgreSQL에서
Spring context가 시작되지 않던 문제를 수정했다.

# 변경 파일

- `src/main/resources/db/migration/V10__create_audit_log.sql`
- `src/main/resources/db/migration/V11__add_reservation_customer_page_index.sql`
- `jariyo-docs/docs/02-data-model.md`

# 실행 명령

```powershell
.\gradlew.bat test
.\gradlew.bat integrationTest
.\gradlew.bat build
```

# 테스트 결과

- `.\gradlew.bat test` 통과
- `.\gradlew.bat integrationTest` 통과
- `.\gradlew.bat build` 통과
- Hibernate 스키마 검증을 유지한 새 PostgreSQL에서 `audit_log` 테이블과 인덱스 생성을 확인

# 이슈

- 감사 로그 구현 커밋에 엔티티와 조회 코드는 추가됐지만 Flyway migration이 누락돼 있었다.
- 현재 작업의 예약 인덱스 migration은 순서를 보존하기 위해 V10에서 V11로 변경했다.

# 후속 작업

- 감사 로그 쓰기 경로는 별도 기능 범위에서 연결한다.

# 셀프리뷰

- `AuditLog` 필드 길이와 null 허용 여부를 migration에 동일하게 반영했다.
- 다형 참조인 `actor_id`, `target_id`에는 특정 테이블 FK를 추가하지 않았다.
- 수정 사항을 이슈 26 기능 브랜치의 commit과 PR에 포함한다.
