# 공통 기반 초기 구성 보고서

## 개요
- 공통 응답 유틸과 멱등성 처리 골격을 추가했습니다.
- 이후 도메인 API가 재사용할 수 있도록 응답 래퍼와 예외 처리 기준을 준비했습니다.

## 변경 파일
- `build.gradle`
- `src/main/java/com/example/jariyo_backend/common/api/ApiResponse.java`
- `src/main/java/com/example/jariyo_backend/common/api/ResponseSupport.java`
- `src/main/java/com/example/jariyo_backend/common/error/BusinessException.java`
- `src/main/java/com/example/jariyo_backend/common/error/ErrorCode.java`
- `src/main/java/com/example/jariyo_backend/common/error/GlobalExceptionHandler.java`
- `src/main/java/com/example/jariyo_backend/common/idempotency/IdempotencyKey.java`
- `src/main/java/com/example/jariyo_backend/common/idempotency/IdempotencyKeyInterceptor.java`
- `src/test/java/com/example/jariyo_backend/common/api/ResponseSupportTests.java`

## 실행 명령
- `./gradlew test`

## 테스트 결과
- `./gradlew test` 성공
- 결과: `BUILD SUCCESSFUL in 4s`

## 이슈
- 전역 예외 처리와 HTTP 응답 타입 사용을 위해 `spring-boot-starter-web` 의존성을 추가했습니다.
- 멱등성 인터셉터는 현재 헤더 확인용 골격만 추가한 상태입니다.

## 후속 작업
- 멱등성 키 저장/검증 로직 추가
- 공통 응답 유틸을 실제 컨트롤러에 적용
- 도메인별 예외 코드 세분화

## 셀프리뷰
- 공통 기반의 최소 재사용 구조를 먼저 만들었습니다.
- 현재는 골격 수준이므로 실제 정책 적용은 후속 도메인 구현에서 이어가야 합니다.
