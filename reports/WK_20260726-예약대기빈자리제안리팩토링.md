# 개요

예약 대기 및 빈자리 제안 도메인 리팩토링을 진행했다.
대기/제안 소유권 검증을 공통 헬퍼로 모으고, 상태 전이 판정을 엔티티 메서드로 일부 끌어올렸으며, 조회 시 비활성 서비스 때문에 상세 조회가 실패하지 않도록 읽기 경로를 정리했다.

# 이슈

- 작업 시점에 `jariyo-docs` 디렉터리에 기존 변경사항이 있어 해당 변경은 건드리지 않았다.
- 이번 작업은 예약 대기/빈자리 제안의 생성, 취소, 수락, 상세 조회에 대한 내부 규칙 정리에 집중했고, 운영자용 제안 제어 API까지 확장하지는 않았다.

# 후속 작업

- 예약 대기 이력과 빈자리 제안 이력 조회 API를 추가할 때 현재 상태 전이 헬퍼를 재사용하도록 구조 확장
- `WAITLIST_NOT_OWNED_BY_USER`를 사용하는 다른 사용자 리소스 도메인과 오류 코드 일관성 검토
- `findMine`, `detail`, `slotOfferDetail` 경로의 조회 최적화와 DTO 전용 조회 모델 분리 검토

# 셀프리뷰

- `04-api-spec.md`, `06-backend-implementation-guide.md`를 다시 확인하고 예약 대기/빈자리 제안 범위에 맞는 리팩토링만 반영했다.
- 문서에 정의된 `WAITLIST_NOT_OWNED_BY_USER`를 코드에 반영했고, 기존 generic 소유권 오류보다 더 구체적인 오류를 반환하도록 정리했다.
- 비활성 서비스가 되더라도 기존 대기/제안 상세를 읽을 수 있게 조회 경로를 조정했다.
- `./gradlew test`로 전체 회귀를 확인했다.
- `reports`에 작업 보고서를 추가했다.
