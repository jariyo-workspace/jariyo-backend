# 사용자 및 권한 워크스트림 구현 보고서

## 개요

- 이슈 #2의 사용자 계정, 고객 프로필, 매장 멤버, 인증·인가 기반을 구현했습니다.
- RS256 Access Token과 회전형 Refresh Token을 적용하고 회원가입, 로그인, 재발급, 로그아웃, 내 정보 조회 API를 추가했습니다.
- PostgreSQL 스키마를 Flyway로 관리하고 UUIDv7 식별자와 매장별 역할 검증 구조를 적용했습니다.
- `auth`, `user` 도메인 내부를 `controller`, `dto`, `entity`, `repository`, `service` 계층 패키지로 분리했습니다.

## 테스트 결과

- 기본 테스트: 성공, 총 18개 테스트 통과
- `integrationTestClasses`: 성공, PostgreSQL 통합 테스트 소스 컴파일 완료
- `integrationTest`: Docker 데몬이 실행되지 않아 Testcontainers 초기화 단계에서 실행 불가
- 전체 빌드: `BUILD SUCCESSFUL`
- 계층 패키지 분리 후 `compileJava`, `test`, `integrationTestClasses`, `build` 재검증 성공
- 검증 범위: 이메일·전화번호 정규화, 비밀번호 정책, 회원가입, RS256 JWT Claim, Refresh Token 회전·재사용 탐지, 쿠키 속성, 401/403 응답, 매장 역할 및 타 매장 접근 차단

## 이슈

- 현재 개발 환경에 Docker 데몬이 없어 실제 PostgreSQL 통합 테스트를 실행하지 못했습니다.
- `jariyo-docs` 변경 커밋 `4154500`은 로컬 브랜치 `docs/user-auth-contract`에 있으며 백엔드 서브모듈 포인터를 공유하기 전에 문서 저장소 원격에 먼저 푸시해야 합니다.
- 운영 실행에는 `DB_URL`, `DB_USERNAME`, `DB_PASSWORD`, `JWT_PUBLIC_KEY`, `JWT_PRIVATE_KEY` 환경변수가 필요합니다.

## 후속 작업

- Docker 사용 가능 환경에서 `.\gradlew.bat integrationTest`를 실행합니다.
- 매장 도메인 구현 시 `store_member.store_id`에 `store.id` 외래키를 추가합니다.
- 문서 브랜치를 원격에 푸시하고 문서 PR을 먼저 생성한 뒤 백엔드 PR의 서브모듈 포인터를 확인합니다.
- 직원 초대·생성·수정·비활성화 API는 매장 운영 워크스트림에서 구현합니다.

## 셀프리뷰

- `01-plan.md`, `02-data-model.md`, `04-api-spec.md`, `05-frontend-api-guide.md`, `06-backend-implementation-guide.md`, `07-backend-mvp-guide.md`를 확인했습니다.
- 데이터 모델과 API 계약이 바뀐 `02`, `04`, `05` 문서를 함께 수정했습니다.
- `feature/user-auth-permission` 브랜치에서 작업했으며 `master`에 직접 커밋하지 않았습니다.
- 기본 테스트와 전체 빌드를 실행했고 Docker 제약 및 미실행 통합 테스트를 기록했습니다.
- 설계 범위를 벗어나는 약관 동의 이력, 직원 초대, Store 엔티티는 추가하지 않았습니다.
- Refresh Token 원문과 RSA 개인키가 저장소에 기록되지 않는지 확인했습니다.
- 도메인 내부 클래스의 package 선언과 테스트 경로가 실제 디렉터리 구조에 일치하는지 확인했습니다.
